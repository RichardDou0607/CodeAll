## Standards 轴发现

### S1 · 高优先文档一致性缺陷：docs/26 与同批 CLI-1 纠偏口径矛盾

新增 [docs/26-v0.3.0-scope.md:11](../docs/26-v0.3.0-scope.md) 称 ZCode `account:*` 被上游 Provider Registry 拦截后「**现回退 UI 粘贴**（需辅助功能权限、App 前台）」；[第 33 行](../docs/26-v0.3.0-scope.md) SPIKE-4 ② 的「UI 粘贴通道加固」同源预设。

而同一批工作区改动刚按 docs/25 §2 CLI-1 把 `docs/40-adapters.md` §3.12/§3.14 与 `demo/README.md` 纠偏为：UI 粘贴回退在当前接线下**不可达（既有死代码）**；`account:*` 实际走 app-server 管道，无 provider 时**如实失败**（不谎报送达）。「打开会话」是唯一可见通道。docs/26 于 10-17 11:57 先行成稿，晚于其后的 docs/40（19:23）与 demo/README（19:06）纠偏未同步更新，属**陈旧表述**而非「反向漂移」；[第 52 行](../docs/26-v0.3.0-scope.md) 风险表仍写「沿用 ZCode UI 通道既有模式」，同源预设应一并改。本项不引编码规范（仓库无 AGENTS/CONTRIBUTING/CODING_STANDARDS 等规范文件），按**文档一致性缺陷**定性，优先级仍为应改。

**调整**：改写 docs/26 §1 表格行、SPIKE-4 措辞与 §5:52 风险表为「管道投递 + 无 provider 时如实失败；UI 粘贴仅为代码中保留但当前不可达的旧回退，是否复活待 SPIKE-4 结论」。

### S2 · 嗅觉（判断题）：`isolatedEnv`/`DSH_SCRUB` 三份同形实现

`demo/test-env.mjs:17`、`scripts/perf-baseline.mjs:31-32`、`scripts/perf-verify.mjs:80-81` 各有一份 `DSH_SCRUB` + `isolatedEnv()`（后两者逐字相同；test-env 版含绝对路径校验与 DSH_HOME 注入，但无 TMPDIR 隔离）。`scripts/perf-baseline.mjs` 已跨目录 import `demo/test-model-fixture.mjs`，证明跨目录复用通道成立。

**调整建议**：三处收敛到 `demo/test-env.mjs` 导出（需把 perf 脚本的 TMPDIR 隔离并入 helper），两个脚本 import。

### S3 · 嗅觉（判断题）：zcode-adapter 退避逻辑重复

`adapters/zcode-adapter.mjs:328`（`slowDown()`）与 `:380`（`pump()` 尾部）各写一次 `Math.min(backoffMs * 2, 10_000)`，两处语义相同（无新行即翻倍退避）。

**调整建议**：`:380` 改调 `slowDown()`，封顶值收为单一常量。

### S4 · 嗅觉（判断题）：framed 三个缓存形状重复（Duplicated Code / Data Clumps）

`demo/framed.mjs:270`（`catalogCache`）、`:284`（`wsCache`）、`:295`（`multiCache`）同为 `{at, data, key}` + TTL + `stableJson` 比较的形状。

**调整建议**：提取共享 `makeTtlCache(ttlMs)` helper。属可选重构，不阻塞发布。

### S5 · 可选清理（不计入规范轴发现）：window.html 计时回退分支不可达

`demo/window.html:1033`：`sinceNum` 在缺 `since` 时回退 `now − elapsedMs`。复核：`now` 取 `snap.ts`（Hub 快照 ts，window.html:822），`elapsedMs` 亦为 Hub 字段，该回退是**同一 Hub 帧内两字段相减**，不读本地时钟；docs/51 §3.2 T2 明确允许「`snapshot.ts − session.since`（同帧两字段相减，仍不读本地时钟）」；契约 §5.3 的 `sessions[].since` 为必填且 `snapshot()` 恒带 `since`（demo/framed.mjs:559；初值 :406/:411、变更 :424），故回退实际不可达。**结论：不构成契约擦边**，列为可选死代码清理（删除回退或保持现状），不计入 Standards 轴发现。

另：`startFollower` 的 `read()` 闭包兼管轮转检测/增量读/解码/滞留/离线边沿，单一函数多因变化（Divergent Change 苗头），登记备查，本版不动。

### P1 · PERF-2 证据链缺口（>50MB 口径 + 乱序/坏帧断言）

docs/25 §3 PERF-2 行（[:38](../docs/25-v0.1.1-scope.md)）声称「>50MB 独立测量 0 B vs 旧 ~2.64GB（附录 C）」。核对结果：

- 同一说法还出现在 [docs/25:63](../docs/25-v0.1.1-scope.md)（量化口径「直接测量：>50MB…」）、[docs/25:105](../docs/25-v0.1.1-scope.md)（「应 ≈0」的估算锚点）、[docs/CHANGELOG.md:14](../docs/CHANGELOG.md) 与 [:44](../docs/CHANGELOG.md)，口径修整须一并覆盖；
- PERF-2 完成条件还要求「乱序/坏帧/半帧/轮转」合成断言（[docs/25:38](../docs/25-v0.1.1-scope.md)），但 perf-verify P2-correct（[:320-353](../scripts/perf-verify.mjs)）仅覆盖半帧 + 轮转，「乱序/坏帧」无断言。

**调整**（二选一）：补 >50MB 档实测入册（须用 `git worktree`（HEAD=f577807）对照旧码，否则新码实测仍不能证明旧实现 ~2.64GB），并把「乱序/坏帧」断言补进 perf-verify；或将 docs/25:38/:63、附录 C 与 CHANGELOG:14/44 的 >50MB 口径改为「8MB 实测 0 B + >50MB 估算推算」，去掉「独立测量」表述。

### P3 · PERF-4「15s TTL + 2s 节拍」口径命名不精确

docs/25 §3 PERF-4 行（[:40](../docs/25-v0.1.1-scope.md)）「目录/四态变化 ≤~17s 可见（15s TTL + 2s 节拍）」：实测中 TTL 为**惰性缓存**（无独立触发），静默可见性实际靠四态 mtime（15s）+ `WORKSPACE_STORE` mtime 5s 信号驱动（[:59](../docs/25-v0.1.1-scope.md) 终轮实测 11.0s 即此路径）；不改变 mtime 的静默变化须待下次任意快照构建才被 TTL 覆盖。对应 perf-verify 检查名「目录 TTL」名不副实。延迟数字与机制均真实，**仅命名与归因口径需校准**（注：§4 表格 [:59](../docs/25-v0.1.1-scope.md) 已写「四态 mtime + `WORKSPACE_STORE` mtime 5s 静默信号 + 15s TTL 兜底」，本身无需改；待校准的是 PERF-4 行的「15s TTL + 2s 节拍」）。

**调整建议**：docs/25 PERF-4 行（:40）改为「mtime 静默信号驱动（≤5s/15s）+ 惰性 TTL 兜底」；perf-verify 检查名「目录 TTL 15s」（:266）同步。
