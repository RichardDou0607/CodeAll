**观察项（不阻塞验收，登记备查）**：claude-code 在无头新建后约 1 分钟内立即 `--resume` 同一会话，出现一次 `No conversation found with session ID`（CLI 侧会话索引未就绪窗口）；队列如实回报 failed，确认后重发即送达。手动同环境复现正常（净化 env 亦正常），时间窗 1–4 分钟后消失。影响：新建后立刻发第二条的用户可能遇到一次诚实失败 + 重发；豁免不了 V01（第二轮最终在同一 ID 完成），但值得在 v0.2 调研 CLI 会话索引的就绪信号。

## V04 证据

- CLI 早期退出（合成，`demo/test-crash-window.mjs` 场景 D1）：mock CLI 立即非零退出 → 队列 failed，detail 带日志尾巴「Not logged in (mock)」，不谎报已投递。
- 服务重启回归：重启前 sessions=8 / 队列无非 delivered 条目 / plugin=true → 重启后服务恢复、队列无幽灵「结果未确认」（全部干净完成）、五个验收会话全部回到目录、插件重连；重启后向 DSH 会话投递一轮，回复 "recovered"、turn/end completed。

## V05 证据

- 代码：`demo/framed.mjs` `upsertInput()`（按 id 原位替换）+ 四处执行前落盘（新建、CLI 无头、DSH 插件、失败重试原位置 pending）；终态原位更新，同一消息不产生第二条队列记录。
- 合成回归 `demo/test-crash-window.mjs`（隔离 HOME + mock CLI + 假插件）四场景全过：
  A CLI 续会话投递中 kill -9；B 插件 4s 窗口内 kill -9（假插件已收到请求即「可能已送达」）；C 投递即新建执行中 kill -9；D cli-exit 快速失败 + 重发执行中 kill -9。
  断言：重启后条目在、status=failed、detail 含「结果未确认」、原文/目标/来源保留、文件内单条不增殖、重启后不自动重发。
- 幂等边界维持 docs/23 §2 口径（不承诺 exactly-once；已接收条目重发需 confirm）。
