## 1. 现状确认（2026-10-17 本机实测，证据等级 [A]）

| 桌面 App | 进程内/官方通道 | 实测结论 |
|---|---|---|
| **DSH（DeepSeek Harness）** | Cordis 插件 + Unix socket（docs/54） | ✅ 唯一已打通的进程内双向通道（自有软件可挂插件）；输入/打开/新建/事件全通 |
| **ZCode** | 官方 app-server 管道（docs/40 §3.12 [A]）+ `zcode://` 深链 | ✅ personal/builtin provider 投递+新建已落地；❌ account:*（Coding Plan 登录态）被上游 Provider Registry 拦截 → 管道投递**如实失败**（不谎报送达，口径见 [docs/25](./25-v0.1.1-scope.md) §2）；代码中保留的 UI 粘贴回退在当前接线下**不可达**（`deliverViaCli` 对 zcode 无条件先走管道，见 docs/40 §3.14），是否复活待 SPIKE-4 结论 |
| **Kimi Code** | 运行中实测：`127.0.0.1:50394`（404 内部服务）、`50395`（内置 Kimi Web 客户端 HTML） | ❌ 两个回环端口均无会话输入 API；无 AppleScript 字典；现走 CLI 共享 wire.jsonl（桌面 App 是否感知外部写入 [U]） |
| **Claude 桌面** | Electron（app.asar），无 AppleScript 字典（sdef=0） | ❌ 无已知输入接口；会话数据与 CLI 共享 `~/.claude/projects`（现走 CLI 无头 resume） |
| **Codex++ 桌面** | Electron，无 AppleScript 字典（sdef=0） | ❌ 无已知输入接口；rollout 与 CLI 共享 `~/.codex`（现走 CLI 无头 resume） |
| 通用结论 | — | **五家 App 均无官方 AppleScript 脚本面**；除 ZCode 外无官方外部输入协议；「进程内插件」模式仅对自有软件（DSH）可行 |

## 2. 攻坚目标定义

「桌面端信息传输」= 双向：

- **入（控制）**：把消息 / 模型选择 / 新建会话指令送进**正在运行**的桌面 App 会话，替代或补充 CLI 无头续接（现状：Claude/Codex/Kimi 桌面会话被 CLI 进程接管，App 内不可见或不感知）；
- **出（观察）**：桌面 App 会话的实时事件。现状文件级观察已覆盖五源；进程内实时事件目前只有 DSH 插件与 ZCode 管道两条。

优先顺序：入 > 出（出已有文件级兜底，入是能力缺口）。

统一约束：不注入、不改第三方 App 配置、不读凭证；UI 自动化仅作最后手段且必须辅助功能权限显式授权；每张证据卡标注 [A]/[B]/[U]。

## 5. 验证纪律与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 第三方 App 无任何输入接口（spike 最坏结论） | 该家标「不可控制」降级观察 + 诚实展示，不虚构 | 证据卡 [A] 落定即收口；UI 自动化不默认强上 |
| App 更新导致协议/端口漂移 | 通道失效 | 每通道加版本探测 + 失效自报；文档标注实测版本号 |
| 辅助功能权限（UI 自动化路径） | 用户拒绝则通道不可用 | 权限前置探测 + 引导设置（若 SPIKE-4 复活 ZCode UI 粘贴通道则沿用其权限前置模式；当前接线该通道不可达，见 §1） |
| 桌面 App 进程内写入共享会话文件冲突 | 数据损坏 | 只做只读观察 + 官方通道控制；无官方通道不动手 |
