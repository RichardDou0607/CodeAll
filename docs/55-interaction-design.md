# 55 · 人机交互总体方案（v1，2026-10-06）

> 定位：把**已实现**（软件四态面板 / 会话目录 / 项目切换 / 投递目标 / 输入队列 / 新建·打开）与**规划中**（多源会话 M-A/B/H、控制通道 M-D/E、远端 AgentOS 主机 M-J2/3、供应商标签 M-K、用量）的全部功能整理成**一套统一的交互方案**。
> 与 [51-work-frame-spec.md](./51-work-frame-spec.md) 的关系：51 定义**悬浮卡片**的像素级规格（本文称「常驻层」）；本文定义**双面模型**（常驻层 + 控制台层）及全部功能的交互规则。**冲突时**：卡片内布局/常量以 51 为准；跨面流转、控制台布局、软件区/会话区/动作区交互以本文为准。
> 沿用的硬约束（不重复论证）：51 §1.1 五原则（P1 状态先于角色 … P5 打扰可退）、P3 零推断（一切取 Hub 快照）、P4 降级显式（不假装正常）；契约 v1.3 能力位（canCatalog/canOpen/canCreate/canDecide）。
> 证据分级：**[已实现]** 当前 demo/window.html 已有；**[新规]** 本文定义的行为变更；**[规划]** 对应 docs/21 里程碑，随里程碑落地。

## 0. 现状痛点（为什么需要整理）

功能都在，但交互是「长出来」的，不是「设计出来」的：

| # | 痛点 | 现状 |
|---|---|---|
| 1 | **三个过滤器没有层级**：项目下拉、历史开关、软件来源各自为政；用户不知道「为什么这行不见了」 | [已实现] 项目过滤 + 历史开关；软件维度无过滤 |
| 2 | **软件面板是死信息**：四态只能看，不能点；「已打开·未连接」用户不知道下一步该干什么 | [已实现] 面板纯展示 |
| 3 | **投递目标与过滤器互相打架**：目标会话被项目过滤掉时静默回退「自动」，用户以为投给了 A 实际投给最新会话 | [已实现] 静默回退 |
| 4 | **新建按钮常灰**：能力位不够时只有 tooltip 解释，没有「为什么/怎么办」的路径 | [已实现] 禁用+title |
| 5 | **队列术语不统一**：queued/pending/delivered/failed 的用户文案与颜色没有一张统一表 | [已实现] 但散落 |
| 6 | **卡片与演示窗是两个世界**：51 的悬浮卡片只有状态，demo 窗有全部控制能力，二者没有定义流转 | 规格缺口 |

## 1. 设计目标与三个使用时刻

用户（开发者本人 / 小团队）与总控的接触按投入程度分三档，**每档只解决一件事**：

| 时刻 | 用户在做什么 | 耗时 | 承载面 |
|---|---|---|---|
| **瞄一眼**（awareness） | 「它们都在干活吗？有没有等我的？」 | < 1 s，不点任何东西 | 常驻层（卡片/窄条，51 全规格） |
| **管一管**（control） | 过滤、选中目标、发一条输入、新建/打开会话、看软件连接状态 | 5–30 s | 控制台层（本文核心） |
| **交给它**（delegation） | 长任务交给 agent，人离开；回来验收 | 异步 | 常驻层通知 + 控制台历史/队列 |

**裁决原则（沿 51 五原则排序）**：任何新功能先问「属于哪个时刻」；瞄一眼的时刻**禁止**出现需要点击才能理解的信息；管一管的所有操作 ≤ 2 次点击可达；交给它的结果**永远留痕**（队列/历史/已清理计数）。

## 2. 双面模型（信息架构总图）

```
┌─────────────────────────────────────────────────────────────────┐
│  常驻层（悬浮卡片 / 窄条 / 宠物脚下迷你条 —— 51 全规格，不改）        │
│  职责：瞄一眼。四项常驻 + 会话行（≤5）+ ⏳ 未决入口                  │
│  入口：⏳ 待办 / 点击会话行 / ⌥⌘C / ⌘点击卡片                       │
└───────────────┬─────────────────────────────────────────────────┘
                ↓ 展开（不重连 Hub，快照 ts 连续 —— 沿 51 WF-21）
┌─────────────────────────────────────────────────────────────────┐
│  控制台层（= demo/window.html 演进版，一个普通可停靠窗口）            │
│                                                                   │
│  ┌ 标题栏：聚合状态 · ⌘K 搜索 · ⚙ 设置 · ↗ 常驻卡片                ┐
│  ├ ① 软件区：四态面板（每行 = 软件 × 状态 × 动作）                  │
│  ├ ② 会话区：筛选条（软件 chip ‖ 项目下拉 ‖ 活跃/历史）+ 会话行列表  │
│  ├ ③ 动作区：投递目标 chip + 输入框 + 发送                          │
│  ├ ④ 队列区（可折叠）：待投递/已送达/失败 + 重发/删除/清空           │
│  └ 状态脚注：数据源 · 扫描耗时 · 最后事件 · 降级角标                ┘
└─────────────────────────────────────────────────────────────────┘
```

**面间三规则**：
1. **同源双视图**：卡片与控制台渲染同一份 Hub 快照（零推断沿用）；控制台的筛选状态**不写回**卡片（卡片永远显示全局聚合）。
2. **控制台可关，常驻层不可关**：控制台只是工具窗；关掉它不影响任何状态显示（51 P5 精神的推广）。
3. **待办是唯一双向入口**：卡片 `⏳N` ⇄ 控制台待办视图；这是「等我的」最高优先级通路，两侧计数永远一致。

## 3. 软件区交互（四态 × 动作）[新规]

四态面板从「死信息」变成「总控的组织中枢」：**每个状态对应一个明确的下一步动作，无死路**。

### 3.1 状态 × 动作表

| 状态 | 行内主动作 | 次动作（右键/⋯） | 点击行本身 | 视觉（沿 51 形状+颜色双编码） |
|---|---|---|---|---|
| **已连接**（打开·已连接） | **「只看它的会话」**：把会话区过滤到该软件（chip 高亮，再点取消） | 打开软件窗口 · 重新探测 · 查看连接证据（evidence tooltip） | 同主动作 | 实心圆 ● 绿 + 通道徽标（插件/日志） |
| **已打开 · 未连接** | **「怎么连接？」**：气泡给一条最短路径（见 3.2） | 聚焦该软件窗口 · 重新探测 | 同主动作 | 半环 ◐ 黄 |
| **未打开** | **「启动」**：`open -a`（App 类）或终端新标签起 CLI（CLI 类；仅启动，绝不装/升） | 打开安装位置（Finder） · 上次活动时间 | 同主动作 | 空心圆 ○ 灰 + 上次活动相对时间 |
| **未下载** | **「安装指引」**：气泡给出官网/命令 + 该软件的接入计划里程碑（如 KimiCU → C 级观望） | 复制安装命令 | 同主动作 | 虚线圆 ◌ 暗灰 |

> **启动动作的安全边界 [新规]**：总控只调用系统 `open`/新建终端标签，**不代装、不代升级、不代配置**（与「不碰凭证」同级的红线；安装永远是人确认的动作）。

### 3.2 「怎么连接」指引内容（按软件差异化，P4 降级显式的推广）

| 软件 | 已打开·未连接时的指引文案 |
|---|---|
| DSH | 「挂载 Cordis 插件后 <1ms 事件直连（未挂载时走日志兜底，状态照常）」→ docs/54 链接 |
| Claude Code | 「在终端/VSCode 里开启一个会话，转录有写入即自动连接」 |
| Codex | 「CLI 当前不在 PATH（计划 M-E 需恢复）；先启动 Codex++ 产生会话即可观察」 |
| Kimi Code | 「会话数据位置待定位（计划 M-H Step 1 完成后自动升级为可连接）」 |
| AgentOS M1 | 「终端运行 agent 进入长对话即连接（远端控制见计划 §6）」 |

### 3.3 探测透明度

- 每行 tooltip 列出 evidence（安装路径 / pid 列表 / 通道类型 / 上次活动绝对时间）——「凭什么说它已连接」永远可查（沿 51 §3.4「隐藏指标原因可查」）。
- 探测失败（ps 超时/目录不可读）：该行加 ⚠ 角标 + 文案「探测失败，显示上次结果」，**不**回退成「未打开」（P4：不假装）。

## 4. 会话区交互（选择模型 + 过滤器层级）[新规 + 已实现]

### 4.1 过滤器层级（解决痛点 1）

三过滤器**正交**，取交集；每个过滤器带计数，任何过滤导致 0 行时**给出原因行**而不是空白：

```
[全部软件 ▾/chip 组] ‖ [全部项目（N） ▾] ‖ [活跃 | 历史]     ← 筛选条（正交）
─────────────────────────────────────────
（若结果为空）「Codex × agent桌宠 没有活跃会话 —— 历史里有 3 个 · 清除软件过滤」  ← 原因行
```

- **软件 chip 组**来自软件区已连接的软件（点击软件区行即设置，两侧状态同步）。
- 历史开关改为「活跃 / 历史」分段控件（默认活跃，历史折叠进同一列表尾部并带日期分隔线）。

### 4.2 选择模型三规则（解决痛点 3）

| # | 规则 | 理由 |
|---|---|---|
| S1 | **行点击 = 设为投递目标**（再点取消回自动）；目标行高亮 + 动作区目标 chip 同步 | 已实现，保留 |
| S2 | **过滤器只影响显示，不影响目标**：目标被过滤掉时**不回退**，动作区显示黄色警示条「目标已不在当前视图（被过滤）· 点击定位 / 解除目标」 | [新规] 替换现状的静默回退——静默改投递目标是危险行为 |
| S3 | **「打开」是独立动作**（行尾 ↗，canOpen 能力位控制），不与选择合并；历史行「打开」= 恢复会话上下文定位 | 打开 ≠ 我要往里投递 |

### 4.3 会话行与排序

- 行结构沿用现状（状态点 · source 徽标 · 标题 · 「软件 · 模型 · 思考程度」meta · 状态 · 计时 · 待办 N），与 51 §2.1 会话行分区兼容。
- 排序沿 51 §5.1：`waiting > error > working > thinking > done > idle`，同级按最近事件倒序；新 waiting 置顶高亮 3s。
- **搜索 [新规]**：`⌘K` 聚焦，匹配 标题/项目名/软件名/会话 ID 前缀；↑↓ 导航，Enter = 选中首个为投递目标并清除搜索。

### 4.4 远端主机分组（[规划] M-J2，Phase 3）

- source `agentos@<host>` 的会话归入**主机分组头**（`▸ server-a · 2 会话`，可折叠）；主机分组排在本地会话之后。
- 主机分组头自带四态复用：在线（绿）/链路中断（灰+断链图标，「重连中」）——远端离线语义按 docs/21 §6.5（链路中断 ≠ 会话结束）。
- 投递到远端会话 = J3 通道（`ssh <host> agent -s`），动作区目标 chip 加主机徽标。

## 5. 动作区交互（输入与投递）[已实现 + 新规]

### 5.1 布局与焦点

```
┌ 动作区 ─────────────────────────────────────────────┐
│ 投递目标：[CLAUDE-CODE · api-fix ×]   ← chip；默认「自动 · 最近活跃主会话」 │
│ [ 输入框（Enter 发送 / Shift+Enter 换行 / ⌥⌘I 聚焦） ]               │
│ 通道提示（左侧）                          [发送]（右侧）              │
│ ▸ 队列（N）（可折叠）                                                │
└─────────────────────────────────────────────────────┘
```

- **草稿持久化 [新规]**：输入框内容随项目/软件过滤切换与窗口关闭保留（写入 `~/.agent-pet/draft.txt`，0600，≤2000 字符）——现状切视图即丢。
- **能力位降级显式**：目标软件 canInput=false → 输入框 placeholder 与通道提示改为「将进入本地队列（该软件暂无直投通道）」，队列区同时高亮；**不**禁用输入框（队列是合法路径，不是错误）。

### 5.2 发送反馈与队列生命周期（解决痛点 5，术语统一表）

用户可见文案**只用四个词**，颜色固定：

| 内部状态 | 用户文案 | 颜色 | 可做 |
|---|---|---|---|
| queued | 待投递 | 黄 | 复制 · 重发 · 删除 |
| delivered | 已送达 | 绿 | 查看去向（via 通道 + 目标会话） |
| failed | 失败 | 红 | 失败原因 tooltip · 重发 · 删除 |
| （取消） | 已取消 | 灰 | —（删除后 5s 内可撤销 [新规]） |

- 送达/失败的 toast ≤ 3s 自动消失；「已送达」点击 toast 可定位目标会话行。
- 队列默认折叠为「▸ 队列（N）」，有待投递/失败时自动展开一次。
- **重发语义**：从原目标重发；送达后原条目自动删除（已实现，保留）。

### 5.3 新建会话（解决痛点 4）

- 入口：「+ 新建」按钮 → 二级浮层：**软件（已连接且有 canCreate 的才可选）+ 项目（cwd，可新建目录）+ 可选模型/思考程度**。
- 无任何可建软件时按钮禁用，浮层仍可打开并**逐软件解释原因**（「Claude Code：新建需终端起进程，计划 M-D」「Codex：CLI 不在 PATH，计划 M-E」）——把「为什么不能」变成「什么时候能」。
- 新建成功：会话行出现（waiting→idle），toast 带「查看」定位。

## 6. 打扰与通知策略（沿 51 §4.6 扩展到控制台）

| 事件 | 卡片/窄条 | 控制台 | 声音（默认关） |
|---|---|---|---|
| waiting（审批/提问） | ⏳N + 1Hz 脉动（51 规格） | 待办入口红点 + 该会话行置顶高亮 | 可选轻提示 |
| 持久 error | 红常驻（51 §3.1） | 会话行红 + 队列区角标 | 无 |
| 输入已送达/失败 | 不打扰 | toast ≤3s + 队列状态 | 可选 |
| 软件离线/连接恢复 | 角标（51 §3.5） | 软件区行状态翻转 + 一次性 toast「Codex 已连接」 | 无 |
| 远端链路中断（规划） | 角标 + 主机分组头灰 | 同左 +「重连中」 | 无 |

**规则**：勿扰三档（关闭/专注/完全静默）抑制 toast/声音/抖动，**永不抑制**任何常驻信息（51 §4.6 原文推广到控制台）。
