# 29 · v0.1.4 范围（真相源）：Coding Plan 订阅使用情况面板

> 状态：**已实现，随本轮提交**｜定向：用户 2026-10-26「尝试接入全部主流厂商的 coding plan（需要展示完整的信息）」——经澄清为 **coding plan 的使用情况**（订阅身份 × 本地用量 × 配额/余额），非新增会话观察源。
> 上游：八源观察与用量链路（v0.1.0–v0.1.3 + OpenCode/Qoder/Cursor 扩源）不变；本轮在其上叠加**订阅视角**。

## 1. 问题与口径

用户订阅了多家厂商的 coding plan（GLM Coding Plan、DeepSeek 开放平台、Claude、ChatGPT/Codex、Kimi For Coding、Qoder、Cursor、Copilot……），需要在一个地方回答三个问题：

1. **订阅的是什么档位**（计划身份）；
2. **用了多少**（本地可观测的用量时间窗）；
3. **还剩多少 / 花了多少**（配额或余额）。

**证据边界（2026-10-26 本机只读侦察，全部 [A] 实测）**：

| 厂商 | 计划身份（本地） | 本地用量 | 云端配额 |
|---|---|---|---|
| 智谱 Z.ai（ZCode） | **有**：`~/.zcode/v2/coding-plan-cache.json` entitlement 缓存（available/not_entitled）+ 凭证键名（只取名字） | **最强**：`db.sqlite` 的 `model_usage` 表逐请求账本（provider_id 区分登录态 coding plan 与自备 key） | 无缓存 |
| DeepSeek（DSH） | 有：`~/.dsh/.dshw-usage.json` 余额账本（CNY） | **最强**：余额 + 逐日成本 + 逐事件成本/tokens | **本地即有**（余额即配额） |
| Anthropic（Claude Code） | 本机**未登录订阅**（无 oauthAccount、无钥匙串凭证；settings env 有 ANTHROPIC_AUTH_TOKEN 键名 → API Key 计费形态） | 有（转录精确累计，已有） | 无缓存 |
| OpenAI（Codex） | `auth.json` `auth_mode=apikey` → **API 计费非订阅**；若为 chatgpt 模式则解 JWT 白名单 claim（chatgpt_plan_type） | 有（rollout 精确累计，已有） | 无缓存 |
| Moonshot（Kimi Code） | OAuth 登录态（scope=kimi-code、region=mainland-cn）；**订阅档本地不落盘** | 有（usage.record 精确累计，已有） | 无缓存 |
| 阿里（Qoder） | 登录身份有（app-status.json）；**主订阅档未缓存**（partner_plan_snapshots 仅合作伙伴资格） | 请求级（token 云端，已有口径） | 无缓存 |
| Cursor | **有**：state.vscdb `cursorAuth/stripeMembershipType`（本机=free） | 请求级/估算（token 云端，已有口径） | 无缓存 |
| GitHub Copilot | **有**：VS Code state.vscdb `copilotSku`（本机=free_limited_copilot）+ `~/.copilot/data.db` 账户行 | 无（Copilot 不在八源观察内） | 无缓存（客户端在线拉 get_account_quota） |
| Gemini / Qwen / iFlow / MiniMax / Trae / Windsurf / CodeBuddy | 本机**零痕迹** → 如实标「未安装」 | — | — |

**结论**：各家云端配额数值本地均无缓存；读取需持凭证调厂商 API——**触碰凭证违反安全红线（docs/40 §3.14、CHANGELOG 2026-10-22），不做**。本面板 = 本机只读证据的最大诚实呈现：身份层逐家提取元数据（**凭证值绝不读入**，JWT 只解白名单 claim，账号/邮箱一律打码），用量层复用八源扫描，配额层仅本机有账本者（DeepSeek 余额）展示。

## 2. 实现（MP1–MP7）

- **MP1 `adapters/plan-usage.mjs`**：15 家主流厂商注册表（8 家有 probe 提取器 + 7 家安装检测）；`scanPlanUsage({usage})` 一次产出 `{summary, redline, plans[]}`。ZCode `model_usage` 按 provider 聚合（一条 GROUP BY，含今日/7日/30日窗口列；`account:*` 前缀 = 登录态 coding plan 计费，其余 = 自备 API key 并如实提示到对应厂商行）。
- **MP2 DeepSeek 余额账本**：`.dshw-usage.json` → `quota={kind:'balance', balance, todayCost, d7Cost, d30Cost, allCost, daily[14], events[5]}`；**单位换算 1 单位 = 1e-8 元**（实测 debitUnits 1,676,000,000 ≙ 16.76 元、creditUnits 50,000,000,000 ≙ 充值 500 元）。
- **MP3 GLM 用量窗口**：ZCode provider 拆分（精确）+ OpenCode `glm*` 模型名聚合（近似，标注）合并出 today/d7/d30/all 四窗。
- **MP4 服务接线**（framed.mjs）：`planUsageCache`（身份层模块内 60s 缓存）；`refreshUsage` 完成后跟随刷新；`GET /api/plan-usage` 懒触发（同 `/api/usage` 模式）。快照不带该块（无会话身份，避免 SSE 膨胀）。
- **MP5 UI**（window.html）：用量页「Coding Plan 使用情况」区——表格列：厂商·产品 / 计划身份 / 状态 / 今日 / 7日 / 30日 / 全部 / 配额·余额；未安装行合并展示；每行 `<details>` 证据与明细（GLM provider 拆分表、DeepSeek 近 14 日成本与最近事件、各文件证据行）。打开用量页懒加载、usage.generatedAt 变化即重拉（与日历同模式）。
- **MP6 回归** `demo/test-plan-usage.mjs`（MU-PU1～PU7）：fixture 假家目录 + 假 sqlite（model_usage 窗口分桶、ItemTable SKU/档位键、accounts 表）+ 假 overview 三口径透传 + **隐私断言（输出 JSON 不含凭证值/完整账号）** + UI 渲染断言。3 项全绿。
- **MP7 既有回归适配**：`test-usage-calendar.mjs` 的请求数断言改为按 `/api/usage/calendar` 路径过滤（用量页新增 plan 请求后总请求数变化），并让 mock 对 `/api/plan-usage` 单独应答；其余窗口/重试/去重语义不变（6/6 通过）。

## 4. 不做的事（边界）

- **不持凭证调厂商云 API**（Cursor accessToken、Copilot token、各家 OAuth token 均不读值、不外发）——云端配额数值如实标「云端配额本地不落盘」。
- **不把 GitHub Copilot 加入八源会话观察**（本轮是订阅面板，不是新观察源；Copilot 行如实标注「不在会话观察八源内」）。
- **不虚构档位**：本地无缓存档位的厂商（Qoder/Kimi）显示「已登录 · 档位未知」，不猜。
- ZCode entitlement 缓存可能滞后于真实订阅（缓存时间戳随行展示），实际计费以 `model_usage` provider 拆分为准。
