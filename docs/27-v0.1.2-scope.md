## 2. MRF-1 分钟兜底刷新

- 机制：`demo/framed.mjs` 2s 节拍内——**有 SSE 客户端时**每 `REFRESH_MS`（默认 60s，`PET_REFRESH_MS` 可注入、下限 5s）强制重扫目录五源（`forceCatalogRescan` + 脏标记 → 全量快照推送）并触发用量重扫；用量完成即 broadcast，客户端按 `usage.generatedAt` 翻新自动重拉日历。**无客户端时跳过**：保住 v0.1.1「纯空闲零后台扫描」口径（perf-verify P3③ 继续成立）。计时锚定服务启动时刻（锚 0 会让首个客户端连上的节拍立即触发，污染测量窗口——实现途中抓获）。
- 效果：mini 条状态与日历桶计数最迟 ~1 分钟可见；实时事件路径（跟随器 → 即时推送 ~500ms 级）不受影响。
- 回归：`demo/test-minute-refresh.mjs`（5/5：有客户端首轮自动扫 + 追加 ≤1 周期吸收 + 全量推送；无客户端 ≥2 周期零后台重扫；新会话文件 ≤周期+节拍可见）；perf-verify 各窗口用 `PET_REFRESH_MS=600000` 隔离。

## 3. PERF-7 用量扫描四级增量

### 3.1 实测基线（2026-10-19 评审提供；「1.1GB≈2s」旧口径作废以此为准）

| 源 | 全量耗时 | 语料 | 稳态增量 |
|---|---|---|---|
| Claude | 4,951ms / 166 文件 | 1.09GB | 近 7 天 0 |
| Codex | 2,544ms / 45 文件 | 177MB | 0.1MB/7d |
| Kimi | 2,038ms / 26 文件 | 265MB | 18.2MB/7d |
| DSH | 1,335ms / 84 文件 | 53MB | 28.6MB/7d |
| ZCode | 426ms（31k tokens 行 / 141k part 行） | 567MB sqlite | 每轮全表 |

冷启动 `scanAllUsage` 墙钟 4,963ms；全缓存命中 524ms，其中 ZCode 409ms（**稳态 78% 花在 ZCode 全表**）。

### 3.2 P0 前置（评审认定「不先修则测试全绿但账不对」）

- **P0-1** `stats.readBytes` 改实际读取字节（缓存命中 0 / 尾读增量段 / 整读全量；ZCode sqlite 页缓存不可测恒 0），新增 `resumedFiles`/`corpusBytes`——此后所有「省读」断言的证据基础。
- **P0-2** `refreshUsage(force)` → `FORCE_SCAN_OPTS` 五源真强刷（原 `?refresh=1` 无参调用 + CLI `--refresh` 漏传 zcode）；force 跳过检查点加载、扫后覆盖写（坏缓存自愈）；P3①/P3③ 语义不变。

### 3.3 四级机制（细节与口径见 [docs/40 §3.13](./40-adapters.md)）

| 级 | 机制 | 实测 |
|---|---|---|
| ① 事件循环让出 | 文件间 / 512 行 / DSH 帧粒度 / ZCode `iterate()` 游标（**不加 SQL ORDER BY**——无索引时 sqlite 首行前全表物化+排序 ≈228ms 同步块） | DSH 全量扫描 20ms 计时器最大停顿 22ms（原 ~1.3s 整块）；ZCode 23ms（原 ~409ms）；P7-a：64MB 冷扫 5.6s 期间 SSE 最大间隔 2001ms |
| ② 检查点跨重启 | `~/.agent-pet/usage-checkpoint.json`（`PET_USAGE_CHECKPOINT` 可覆盖；0600、唯一 tmp 名原子写、`SCANNER_VERSION` 失效、逐条目丢弃、8MB 护栏） | P7-b：kill -9 重启后 dsh readBytes=0（对照组全量 67,109,043B），追加行被吸收 |
| ③ 增长文件尾读 | DSH 帧边界（末帧「非空且 \n 收尾」才消费否则推迟——截断 zstd 帧**不抛错**而「成功」解出半段，PERF-2 同款坑）+ inode/魔数；Codex `prevTotal/calls.seen` + 字节精确偏移（`0x0A` 切行）+ 64B 锚点哈希；Kimi 同构；**Claude 例外整读** | UCD2/UCB2/UCC3 对抗组：半写补齐 / 同路径更大替换 / fork 累计跨界（Δ=600 非 last=999）/ 重复 callId 跨界 / 尾读状态跨重启 |
| ④ ZCode 水位 | `time_updated` 单调水位 + 2s 重叠 + msgLru（差量新−旧、负截 0、requests 仅首计）+ partLru((sid,callId)) 双 LRU 6000 **随检查点持久化**；staleMiss=「未命中 LRU 且 tc 早于 LRU 最早条目」可观测；异常轮不推进水位（幂等收敛） | 稳态 409ms→**40ms**（`time_updated` 前置短路 json_extract）；spike 回放与真值逐 token 一致 |

### 3.4 spike 结论（[spikes/zcode-usage-watermark](../spikes/zcode-usage-watermark/README.md)，只读真实库）

- **「tokens 只在终态写入」被推翻**：29,781/31,457 tokens 行处于中间态 `finish=tool-calls` → delta 追账而非一次性入账；口径前提重述为「LRU 记忆期内 delta 精确 + 终态后冻结 + 淘汰后重见按冻结跳过（本机实测 0 例，staleMiss 可观测）」。
- **LRU 必须持久化**：不持久化重启实测丢 495 万 token（S3b）。
- lag 分布 p50=13.7s / p99=301s / max=2.35h——固定窗跳过规则会漏计，故 staleMiss 规则按 LRU 最早条目判定。

## 4. 延迟口径（v0.1.2 后现行；v0.1.1 终态见 docs/25 §4）

| 信号 | 最坏端到端延迟 | 依据 |
|---|---|---|
| 目录变化（静默信号未覆盖的极端情况） | 有客户端时 **≤~62s**（分钟兜底封顶；原为无限滞留）；常规路径 ≤~17s 不变 | MRF-1 + PERF-4 |
| 用量（Token/日历） | 文件源 size+mtime 未变零读；增长文件尾读（DSH/Codex/Kimi，Claude 例外整读）；ZCode 水位增量（稳态 40ms）；**重启首轮检查点复用（readBytes 0）**；有 UI 连接 ≤~1 分钟兜底重扫；无连接懒触发 | PERF-3 + MRF-1 + PERF-7 |

## 5. 风险登记

| 风险 | 缓解 |
|---|---|
| 检查点损坏/漂移 | 版本失效 + 逐条目丢弃 + `?refresh=1` 五源强刷重建（P0-2 后真实存在）+ 恒等式哨兵（componentsSum / dayIdentityMismatched）保留 |
| ZCode 终态冻结假设被将来写入行为打破 | staleMiss 进 stats 可观测；spike 回放口径入册；refresh 重建兜底；与 followZcodeLogs 假设互引（docs/40 §3.13/§3.14） |
| 尾读锚点失效（同路径替换） | inode + 魔数（DSH）/ 64B 哈希（Codex/Kimi）双校验，失配整读回退；abort/deadline 一律不写缓存不推进偏移 |
| delta 负增量 | 截 0 并文档化（真实世界流式累计单调不减；人为递减字段属已登记合法偏差） |
| 增长末帧永久半写（崩溃残留） | 每轮重读该帧增量（KB 级）不推进；下轮增长后由后继魔数证明边界再消费 |
