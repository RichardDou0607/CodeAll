## 2. 对话的定义

本版保证的是“选主会话 → 发送文本 → 后端在同一会话处理 → CodeAll 看见状态与回复摘要 → 可继续发送”。不要求新建完整聊天客户端，不承诺完整对话正文、逐字流、跨端同步或代用户审批。

- 所有既有会话发送前必须显式选中目标；无目标请求返回 400，不自动选“最近活跃”。CLI 一律通过明确的 session ID 续接；只根据 cwd/进程名找到的 tmux pane 不能证明会话身份，不用于消息投递。
- 列表过滤不改变投递目标；未知、歧义前缀和子代理目标必须拒绝。
- 当前 CLI 的短时启动检测不等于回合完成。后续终态与回复必须从转录/rollout/wire 或进程终态核验，不能把“进程已启动”宣传成“任务成功”。
- DSH 插件离线时诚实显示只读/待投递，不回落到其他后端，不自动更换目标，不绕过凭据；旧 `PET_INPUT_CMD` 不再执行（其输入不带目标 ID）。
- 已可能接收的消息在重启、超时或错误后需人工核对再重发；本版不承诺 exactly-once 投递。
- 旧队列重发需再次解析主会话并核对来源；无目标、已删除或来源变化的条目只保留失败记录，不调用后端。

## 5. 验证纪律

默认只跑隔离 HOME、mock CLI、mock 插件和合成数据测试，不消耗真实模型额度。真实闭环必须在专用测试会话中由用户明确触发或授权；检查过程中不重启/停止用户正在工作的 Agent。

本轮先执行：

```bash
node demo/test-cli-create.mjs
node demo/test-input-api.mjs
node demo/test-window-actions.mjs
node demo/test-window.mjs
node demo/test-mini.mjs
node demo/test-open-routing.mjs
node demo/test-follow-budget.mjs
node demo/test-service-hardening.mjs
node demo/test-crash-window.mjs
node demo/test-model-registry.mjs
node demo/test-model-map.mjs
scripts/check-fixtures.mjs
```

`test-zcode-control` 仅作为保留实验代码的兼容性检查，不代表 ZCode 升回当前必保范围。原 `multi-source-check --live` 会向多个真实 Agent 发消息，不能直接作为本次默认验收命令。

2026-10-09 本轮结果：上述隔离测试均通过（界面行为 33/33），额外的模型注册表、模型名映射和 ZCode 管道 mock 通过；扩展 `multi-source-check` 的 ZCode 扫描性能在当前本机负载下超过旧的 300 ms 阈值，两次运行均有 1 项失败，不属于当前必保链路。真实 CLI/DSH 收发、崩溃窗口持久化与最终安装包仍未验收，不能把当前源码标为已发布的 v0.1.0。

2026-10-10 收口轮：新增 `demo/test-crash-window.mjs`（V05 崩溃窗口，四场景）后全套 16 套隔离测试通过（界面行为 34/34）。**实机验收 V01–V06 全部通过**（专用测试会话、最小自检消息；证据与逐条记录见 [qa/v0.1.0-acceptance-2026-10-10.md](../qa/v0.1.0-acceptance-2026-10-10.md)）：三 CLI 与 DSH 的发送/回复回流/上下文连续、同 cwd 隔离、cli-exit 与重启恢复、崩溃窗口「结果未确认」、含当日修复的安装包干净安装与包内 Node 自起投递闭环。遗留观察项：claude-code 无头新建后 1–4 分钟内 `--resume` 偶发 `No conversation found`（CLI 侧会话索引未就绪，诚实失败 + confirm 重发即成，v0.2 调研）；`/api/new` dsh 成功路径 item.accepted=false 的审计字段不一致（登记 v0.1.x 小修）。

2026-10-09 补丁（审查发现→调研→修复）：① `/api/open` 改为按来源分流——此前插件在线会把 Claude/Codex/Kimi/ZCode 的「打开」全部发给 DSH 插件（必然 open-rejected，界面无反馈），现 CLI 源固定走 Terminal 续接，只有 DSH 会话与目录外 ID 才交插件（`demo/test-open-routing.mjs` 回归，含假插件与 osascript 桩）。② 三处 CLI 跟随器的文件预算（80）改为「按 mtime 优先准入 + LRU 淘汰 + 被淘汰者再活跃时从淘汰点续读」——此前本机 162 个 Claude 转录里只有任意 80 个能产生实时事件，之后新建的会话永不进入实时跟随，直接影响「状态及回复摘要回流」的必保口径（`demo/test-follow-budget.mjs` 覆盖 claude/codex/kimi）。界面「打开」失败原因改为写入状态栏（不再静默）。全套隔离测试通过；ZCode 投递串行链阻塞第二条消息 HTTP 响应的问题（实测 8.7s）不修，已登记为后续任务 [docs/22 DEF-1](./22-post-release-roadmap.md)——按范围属实验能力，不阻塞 V01–V06。③ 与 V04/V06 相关的两项健壮性加固：管道日志目录不可写/队列落盘失败不再让服务崩溃（修复前实测 `EEXIST: mkdir` 未处理异常直接退出进程），并加进程级兜底保持存活；SSE 2s 心跳从 DSH 日志跟随器解耦（无 DSH 会话的机器计时不再冻结）——新增 `demo/test-service-hardening.mjs` 回归。
