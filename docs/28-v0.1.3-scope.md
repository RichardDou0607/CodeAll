# 28 · v0.1.3 范围：手动停止 ≠ 出错（契约 v1.4 · aborted 会话态）

> 生效日期：2026-10-19（Asia/Shanghai，用户反馈驱动：被中断的对话在 mini 条一直显示「出错」）。本文是 v0.1.3 范围、机制与验收的真相源，建立在 [docs/27](./27-v0.1.2-scope.md)（v0.1.2）的代码基础上追加；仅 macOS，与 [docs/24](./24-v0.2.0-scope.md) v0.2.0 跨平台并行不冲突。

## 1. 范围

## 2. 机制

### 2.1 根因（2026-10-19 本机 `~/.zcode` 全库实测）

ZCode 被用户停止时：在飞工具行落盘 `state.status='error'` + 固定取消签名错误文本（`"Agent was cancelled before the subagent…"`、`"Bash was cancelled and the child process was asked to stop"`、`"TaskOutput was cancelled…"`、`"WebFetch was cancelled…"`、`"MCP tool … was cancelled"`），**且不再写回合终态**（当日 0 条 `finish=interrupted`；最近一条是 2026-09-19 旧版行为）。旧链路：`mapZcodeRow` 取消工具 → `tool.result(error)` → `transient-error`；而 `transient-error` 在 `PINNED_PROGRESS` 永不过期，`effectiveState` 只修正 `TIMED_PROGRESS`（thinking/running/working）——目录结论救不了它，mini 条从此常驻「出错」。

### 2.2 三层口径

1. **适配器（`adapters/zcode-adapter.mjs`）**：`isCancelledToolError()`（`/cancell?ed|interrupted/i`，覆盖 string 与 `{message}` 形态）——
   - `mapZcodeRow`：取消工具 → `tool.result` `status:'aborted'`；真错误（File has been modified / fetch failed / …）仍 `error`；
   - 粗状态：`finish=interrupted` → `aborted`（原 `idle`）；真错误工具后 agent 继续 → `running` 不变；
   - **滞留修正回看**：`stale>5min` 时窗口内最后的工具行是取消 → `aborted` 而非 `idle`（真实形态：中断会话尾部 `tool-calls` 消息比取消工具行晚 ~5ms，盖住取消行）。
2. **状态机（`demo/framed.mjs` `applyEvent` + `demo/frame.mjs` hub）**：`turn.end`/`session.end`/`step.end`/`tool.result` 的 `aborted` 分支统一置 `aborted`（原 `turn.end(aborted)` 落 `idle`）；不计 `counters.errors` / `recoveredErrors`；`aborted` 不进 `PINNED_PROGRESS`/`TIMED_PROGRESS`（非进行中、24h 退役照常）；聚合同 `done` 档（`AGG_PRIORITY: 0`）。
3. **前端（`demo/mini.html` + `demo/window.html`）**：标签「手动停止」（`--done` 色系）、mini 时间位「停止」；排序/优先级与完成同级（不抢占 waiting/running/error）；主界面 chips 有 `aborted` 会话时追加「停止 N」（10 分钟窗口，与「完成」同口径）；会话归类与 `done` 同档（短暂展示后进完成档）。

## 3. 验收（2026-10-19 全绿）

- **新增 `demo/test-aborted-state.mjs` 21 项**：取消签名识别 3（正/负/空值与对象形态）+ 映射分流 4（aborted/error/ok/interrupted）+ 目录粗状态 7（含滞留回看三例）+ hub 3（aborted 态、不计错误、turn.end(aborted) 保持）+ mini 渲染 4（「手动停止」标签、「停止」时间位、不抢占 running、不顶掉 waiting）。
- **demo 全部 23 个测试 exit 0**（mini / window / tick / input-api / service-hardening / zcode-control / usage 全系等）。
- **真实库回归**：本机 4 个被中断会话（含当日 07:01「分析实验课需求评估…」、03:24「结束子代理后暂停执行」）正确标 `aborted`（2 主会话 + 2 子代理，子代理不进列表口径不变）；真错误会话无一误判。
- **实机**：v0.1.3 安装包部署后 `/api/state` 会话历史含 `aborted` 行（stateSource `stale>5min→aborted(tool-cancelled)`），mini / window 页面带 `aborted:'手动停止'`。

## 4. 风险与边界

- 取消签名是 ZCode 错误文本的**启发式**（`cancelled|interrupted` 字样）：若未来 ZCode 改文案或把真错误也写成 cancelled，需回来调 `CANCELLED_TOOL_RE`；识别不中时回落旧行为（transient-error），不会崩。
- 用户中断后若同会话再次发消息，正常事件流（`turn.start` → thinking）即时覆盖 `aborted`，无需清理。
- `session.end(reason=aborted)` 在 replay-check 中由「移除会话行」改为「置 aborted 保留」——校验器与实现同步，录制回放报告以本口径为准。
