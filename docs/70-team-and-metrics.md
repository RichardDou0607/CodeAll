# 70 · 团队分工、节奏与验收指标

> 负责人：Lead。状态：DRAFT（2026-10-05）。

## 1. 团队配置（推荐 3 人核心 + 1 弹性）

| 角色 | 人数 | 主责 | 出让（谁兜底） |
|---|---|---|---|
| 客户端/外壳工程师 | 1 | 桌宠外壳、透明窗口/置顶/穿透、托盘、设置、自动更新、签名公证 | 渲染动画（设计兜底） |
| Hub/适配器工程师 | 1 | Hub 状态机、socket 协议、录制回放、适配器 SDK 与 DSH 适配器 | 外壳（客户端兜底） |
| 设计/角色（可半职） | 0.5~1 | 角色设定、动画拆分、气泡文案、皮肤规范、动效验收 | 文案（产品兜底） |
| QA/自动化（弹性，Phase 2 起） | 0.5 | 契约一致性测试、回放回归、崩溃演练、安装包验证 | 由 Hub 工程师兜底 |

单人起步时的顺序：Hub+适配器（先证明「事件能到」）→ 外壳最小可见（透明窗 + 一个状态）→ 角色资产 → 打磨。

## 2. 工作节奏（两周一个 Sprint）

| 环节 | 时长 | 产出 |
|---|---|---|
| Sprint 计划 | 周一 1h | 明确本 Sprint 的 Demo 脚本与验收清单 |
| 周二站立 | 15min/天 | 阻塞项当天升级 |
| 周中 Demo（可选） | 周三 30min | 可运行产物（不接受截图代替） |
| Sprint 评审 | 第二周周四 | 按 §3 的验收表逐条过 |
| 复盘 + 缓冲区 | 第二周周五 | 风险登记册更新（[60](./60-risk-register.md)） |

**Definition of Done（每条都必须满足）**
1. 有可运行产物，且有可复制的运行命令；
2. 契约一致性测试通过（schema + fixture 回放 + 未知事件注入）；
3. 新增/修改的文档已同步（含 90-research-notes 的证据）；
4. 崩溃/断连演练至少做 1 次（kill -9 适配器或桌宠）；
5. 无「未标注的假设」——要么有来源，要么明确写「未验证」。

## 3. 阶段验收指标（Gate）

### Gate 1（Phase 1 结束，8 周）：DSH 桌宠 demo 可对外演示
| 指标 | 目标 | 验证方式 |
|---|---|---|
| 事件可见性 | 思考/工具/审批/完成/报错 5 类状态在真实 DSH 会话中 100% 触发 | 5 分钟演示脚本 + 录屏 |
| 工作框可读性 | 首行 40 px 内可读出「状态 + 动作 + 计时 + 未决」；3 会话高度 = 124 px；第 6 会话折叠 `+N` | [51-work-frame-spec.md](./51-work-frame-spec.md) WF-01/07/08/09 用例 |
| 时延 | 端到端 P95 ≤200 ms | 录制时间戳对比脚本 |
| 稳定性 | 2 小时连续使用无崩溃、无内存增长（RSS 漂移 <10%） | 长跑脚本 |
| 崩溃隔离 | kill -9 DSH / 工作框 / Hub 各一次，Agent 不受影响；45 s 内该 source 标记离线、聚合状态回落（契约 §4.4） | 演练记录 |
| 隐私 | 录制样本通过脱敏扫描（无完整对话正文） | 扫描脚本输出 |
| 安装 | 双击安装包可用；未签名版有明确说明 | 干净机器（或新用户）安装测试 |
| 契约 | 契约 §7 **六条**验收全部通过（1 fixture 回放 / 2 离线兜底 / 3 未知类型 / 4 乱序收敛 / 5 契约一致性 / 6 心跳语义） | CI 输出 |

### Gate 2（Phase 2 结束，20 周）：多 Agent 桌宠可收费/可扩展
| 指标 | 目标 | 验证方式 |
|---|---|---|
| 后端覆盖 | P0 适配器 3 个（Claude Code / Codex / 1 个 ACP 系）全部可用 | 各后端 5 分钟演示 |
| 适配器 SDK | 第三方照文档 1 人日能写出一个新适配器 | 外部试点（1 人）+ 反馈记录 |
| 同时多后端 | 3 个后端并行运行时内存 ≤250 MB、CPU ≤5% | 压测记录 |
| 皮肤系统 | 换肤热加载 ≤1 s，不需要重启 | 演示 |
| 商业闭环 | 付费点（Pro/皮肤）可跑通一次真实交易（或明确不做的决策记录） | 交易截图/决策文档 |

## 4. 沟通与协作规范

- **契约变更**：任何对 [00-interface-contract.md](./00-interface-contract.md) 的改动 = 一个 PR，含「兼容性影响 + 受影响适配器清单 + 回归结果」，Lead 批准。
- **适配器提交**：必须自带 fixture（≥20 行真实事件样本，脱敏）与映射表更新（[40](./40-adapters.md)）。
- **上游依赖**：DSH / Claude Code / Codex 的机制变化由「适配器负责人」每月复查一次，把漂移写进风险登记册。
- **文档即交付**：任何结论必须落在文件里，口头结论视为未发生（本项目所有队友产出都在 `docs/`）。

## 5. 度量（每月看一次，不追求虚荣指标）

| 指标 | 为什么看 | 目标 |
|---|---|---|
| 适配器「首次事件到桌宠」耗时 | 决定新后端接入成本 | ≤2 周（P0 后端） |
| 适配器失效率（事件中断次数/小时） | 反映上游漂移与健壮性 | ≤0.5 次/小时 |
| 工作框停留时长/日活会话占比 | 判断是否真的有用而不是玩具 | ≥30% 的 DSH 会话期间工作框处于前台可见 |
| 用户主动关闭率 | 干扰性指标（最重要） | <10% 安装后 7 天内关闭；宠物层开启率作为「陪伴需求」的观察指标，不作为 KPI |
| 崩溃率（会话内） | 质量底线 | <0.5% |
