# 10 · 总体架构与模块拆分

> 负责人：Lead。状态：DRAFT v0.9（2026-10-05）。依赖：契约 [00-interface-contract.md](./00-interface-contract.md)（已冻结）、DSH 桥接验证 [35-dsh-pet-bridge.md](./35-dsh-pet-bridge.md)（队友 D，进行中）、技术栈 [30-implementation-stack.md](./30-implementation-stack.md)（队友 A，进行中）。

## 0. 产品形态（用户方向，2026-10-05）

**主界面 = 工作框（Work Frame）**：一个常驻的窄条/小卡片窗口，第一职责是**显示 agent 的工作状态与进度**（状态灯 + 状态文本 + 当前动作 + 计时 + 未决审批计数）。
**宠物形象是框内的可选元素**（可关、可换成极简图标），起陪伴与情绪表达作用，不承担信息职责。所有「宠物动画」设计都必须先满足工作框的可读性（见 [50-product-spec.md](./50-product-spec.md) §2）。这一方向已写入契约 [00-interface-contract.md](./00-interface-contract.md) §8（Hub 保证工作框所需的最小投影）。

## 1. 一句话架构

**每个 Agent 后端旁挂一个薄适配器（Adapter），把原生事件翻译成契约 v1 的规范事件，统一汇入本机 Hub（常驻小内核），Hub 独占状态机、计时与录制；工作框（含可选宠物形象）只订阅 Hub 的 `pet.snapshot` 快照并渲染。**

```
┌── Agent 后端（各自独立运行，桌宠绝不阻塞它们）──────────────────────────┐
│  DeepSeek Harness (DSH)   Claude Code   Codex CLI   Cursor   …        │
└───────┬───────────────────────┬───────────┬──────────┬────────────────┘
        │ 会话日志 / hooks / 插件 / SDK / ACP（每条路线见 40-adapters.md）
        ▼
┌── 适配器层 adapters/*（独立进程，崩了不影响后端）──────────────────────┐
│  dsh-adapter   claude-code-adapter   codex-adapter   generic-acp …    │
│  职责：观察 → 归一化 → 脱敏/截断 → 契约 v1 事件                          │
└───────┬───────────────────────────────────────────────────────────────┘
        │  Unix socket $TMPDIR/agent-pet/<source>.sock（行分隔 JSONL）
        ▼
┌── Hub（hub/，单实例常驻）─────────────────────────────────────────────┐
│ ① 归并多适配器  ② 每会话状态机（契约 §4）  ③ 快照广播（订阅者）            │
│ ④ JSONL 录制/回放（~/.agent-pet/records）  ⑤ 权限与隐私闸门  ⑥ 崩溃守护   │
└───────┬───────────────────────────────────────────────────────────────┘
        │  快照流（pet.snapshot）：状态 / 气泡 / 特效事件 / 徽标
        ▼
┌── 桌面外壳 pet-app/（透明置顶窗口 + 托盘）────────────────────────────┐
│  ① 工作框（主界面）：状态灯/状态文本/当前动作/计时/未决审批/会话徽标        │
│  ② 宠物层（可选）：精灵动画、气泡、特效（只渲染快照，不做业务判断）          │
│  ③ 交互层：拖拽/吸边/点击穿透/右键菜单/热键/勿扰/展开详情                   │
│  ④ 设置层：形态（窄条/卡片/宠物）、角色、皮肤、音量、自启、隐私开关          │
└──────────────────────────────────────────────────────────────────────┘
```

## 2. 关键设计决策（ADR 摘要）

| # | 决策 | 理由 | 代价 / 备选 |
|---|---|---|---|
| ADR-1 | **后端一进程一适配器**，而不是把适配逻辑塞进桌宠 | 后端崩溃/升级互不影响；适配器可用任意语言；便于第三方贡献 | 多一层进程与握手成本；备选：全部内嵌（被否，耦合太重） |
| ADR-2 | **Hub 独占状态机**，渲染层无业务状态 | 多客户端（桌宠/CLI/面板/手机）看到同一真相；崩溃重启后状态可恢复 | Hub 成为单点 → 必须做到 <50MB 内存、秒级重启、自身崩溃可自愈 |
| ADR-3 | 传输用 **Unix domain socket + 行分隔 JSONL**（契约 §5） | 本机零端口、零认证、低延迟、易调试（`nc -U`）；Windows 用命名管道 | 跨机/WSL 需 WebSocket 兜底（默认关闭，仅 127.0.0.1） |
| ADR-4 | **事件契约版本化（v1…）**，适配器声明 `contract: 1` | 第二阶段多适配器生态的前提；不兼容即拒收并提示升级 | 需要契约回归测试与兼容策略（见 §6） |
| ADR-5 | **本地优先、零遥测**：默认不联网、不读对话正文 | 读取他人会话日志本身敏感；这是可被信任的前提 | 失去云端同步/排行榜类功能；Pro 的云能力必须显式开启 |
| ADR-6 | **先把 DSH 跑通（Phase 1），但所有 DSH 特有能力只出现在适配器内**，Hub 与桌宠不得出现 `if (source === 'dsh')` | 保证第二阶段「加一个后端」= 加一个适配器 | 早期需要克制把功能直接写进桌宠的冲动 |
| ADR-7 | 提供 **fixture 回放模式**（`--replay fixtures/x.pet.jsonl`） | 没有 Agent 也能开发/演示/做 CI；契约验收的基础 | 需要维护 fixture 与真实事件的偏差 |

## 3.1 工作框模块（apps/frame 或 apps/pet 内的 `frame/` 子模块）

| 组件 | 职责 | 数据来源 |
|---|---|---|
| `StatusPill` | 状态灯 + 文本 + 配色（idle/thinking/working/waiting/error/done） | `snapshot.agg` |
| `NowLine` | 当前动作（最近工具 / 当前步骤）与 `elapsedMs` 计时 | `snapshot.now`（Hub 提供，客户端不做时间推断） |
| `SessionStrip` | 多会话徽标（每会话状态 + 时长），点击展开列表 | `snapshot.sessions[]` |
| `PendingQueue` | 未决审批/提问计数与列表（Phase 1 只读：跳转，不代答） | `snapshot.bubble` + 未决登记 |
| `Counters` | 未知事件/离线源/瞬态错误等健康计数（默认折叠） | `snapshot.counters`、`offlineSources` |
| `PetLayer`（可选） | 精灵动画与气泡；**可关闭**，关闭后工作框仍完整可用 | `snapshot.agg` + 特效字段 |

**用户已确认的默认形态（2026-10-05）**：
- **默认 = 悬浮卡片，首行固定，向下逐行显示会话状态**：首行（高 40 px）= 状态灯 + 聚合状态 + 当前动作 + 计时；其下**每个会话一行**（高 28 px）= 会话名/工作目录 + 该会话状态灯 + 该会话计时/最近动作。
- 行数上限 5（含首行），超出折叠为 `+N` 行并点开列表；窗口高度 = 40 + 28×可见会话数（自适应，最小 40）。
- **宠物层默认关闭**（用户已确认「默认极简，宠物可选开启」）；开启后作为卡片旁的独立可拖拽图层，关闭时不影响任何信息。
- 三种可选形态：**卡片（默认）/ 窄条（320×40，仅首行）/ 宠物形态**；切换不需要重连 Hub。

验收要点（按用户确认的形态改写）：**首行 40 px 内必须能读出「状态 + 当前动作 + 计时 + 未决计数」四项**；每个会话行 28 px 内必须能读出「会话标识 + 该会话状态」；任一后端离线必须有显式角标（不得静默）；3 个会话并行时卡片高度 = 40 + 28×3，第 6 行起折叠为 `+N`。

## 4. 运行时数据与目录约定

| 路径 | 内容 | 生命周期 |
|---|---|---|
| `~/.agent-pet/config.json` | 角色、皮肤、音量、自启、勿扰、隐私开关、适配器启用列表 | 用户级 |
| `~/.agent-pet/records/<source>-<YYYYMMDD>.pet.jsonl` | 规范事件录制（轮转 20MB × 7 天） | 可删，用于回放/取证 |
| `~/.agent-pet/state/<source>.json` | Hub 会话聚合快照（崩溃恢复用） | 秒级刷新 |
| `$TMPDIR/agent-pet/` | socket 与 pid 文件 | 系统清理 |
| `~/.agent-pet/logs/` | 双方日志（默认滚动 5MB × 3） | 可删 |

## 5. 关键流程

### 5.1 启动与自愈
1. `apps/pet` 启动 → 若 Hub 未运行则拉起（单实例锁）→ 订阅快照。
2. Hub 按配置拉起各适配器（指数退避重启：1s→2s→4s…上限 60s，连续 5 次失败标记 `degraded` 并在 UI 显示）。
3. 适配器连接后立即发 `session.start`/`pet.heartbeat`，Hub 回 `{"ack":true,"contract":1}`（契约 §5）。
4. 45 s 无任何事件 → 该 source 标记离线，清空其会话聚合（契约 §4.4）；工作框显示「离线」角标。

### 5.2 一次工具调用的端到端时延预算（P95 目标）

| 环节 | 预算 |
|---|---|
| 后端写事件 → 适配器观察到（日志 tail / hook 返回） | ≤120 ms |
| 适配器归一化 + 脱敏 + 发送 | ≤20 ms |
| Hub 状态机 + 广播 | ≤10 ms |
| 渲染层进入新状态（首帧） | ≤50 ms |
| **合计** | **≤200 ms** |

> 审批类事件（`approval.request`）走强提醒通道：允许额外 100 ms 用于置顶/抖动，但必须保证「后端等待用户时，桌宠提示先于用户发现」。

### 5.3 隐私闸门（Hub 内唯一出口）
- 白名单：只有契约 §3 声明的字段可出 Hub；`message.assistant.text` 默认截断到 280 字符并做正则脱敏（路径、密钥样式、邮箱、手机号）。
- 每个事件可带 `privacy.redacted/fields`（契约 §2）；录制文件同样脱敏，且默认仅本机可读（0600）。
- 用户可在设置里「全量关闭气泡文本」，只保留状态与特效。

## 6. 契约版本与兼容策略
- 适配器在 `ctl:hello` 中声明 `contract: 1`；**契约只有主版本 `v`，没有次版本概念**（文档里的 v1.1/v1.2 是**文档修订号**，不代表事件字段或语义版本）。新增可选字段/新 type 属于向后兼容变更，不改变 `v`。
- Hub 遇到未知 `type` 一律忽略并计数（契约 §7.3），不报错、不降级整体；已知但 no-op 的事件计 `noop`。
- `v` 主版本变化（破坏性）时：Hub 同时支持相邻两个主版本 ≥6 个月，`apps/cli doctor` 明确提示升级路径。
- CI 门禁：契约一致性测试（schema + fixture 回放 + 未知事件注入）必须全绿才允许发版。

## 7. 非功能需求（NFR）

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 外壳空闲内存 | ≤150 MB（**口径：`phys_footprint` 合计**，≈ 活动监视器「内存」列；RSS 仅作参考） | `spikes/tools/footprint-sum.sh` + `ps -o rss=` 采样 10 分钟 |
| Hub 空闲内存 | ≤50 MB（口径同上） | 同上 |
| 空闲 CPU | ≤1%（渲染 <0.5%） | `top -l 60` / Activity Monitor |
| 事件端到端时延 | P95 ≤200 ms（§5.2） | 录制时间戳对比脚本 |
| 崩溃隔离 | Agent 进程零感知；桌宠崩溃自动重启 ≤3 s | 手动 `kill -9` 演练写入验收 |
| 断电/崩溃恢复 | Hub 重启后 5 s 内恢复会话快照 | 集成测试 |
| 安装体积 | ≤120 MB（含资产） | 安装包实测 |
| 无语义泄漏 | 录制文件中不含完整对话正文 | 正则扫描 fixture + 真实录制样本 |

## 8. 与 DSH 的边界（Phase 1）
- **不允许**：读 DSH 的账号凭证、直接改 DSH 安装包、把桌宠逻辑写进 DSH 进程内（除可选插件形态，见 [35-dsh-pet-bridge.md](./35-dsh-pet-bridge.md)）。
- **允许**：只读 `~/.dsh/sessions/**`（zstd JSONL）、只读 DSH 公开配置、可选注册 hooks.json command hook、可选在自己的 DSH profile 中挂载自有 Cordis 插件（该选项以队友 D 的实测结论为准）。
- **兜底**：任何一路都拿不到事件时，退化为「进程存在 + 会话文件 mtime 变化」的粗粒度适配器（`working/idle` 两态），并明确在 UI 标注「粗略模式」。
