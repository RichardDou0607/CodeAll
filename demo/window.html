这一版新增了什么

① 每行显示 Agent 软件名 · 模型 · 思考程度（如 DSH · deepseek-flash · thinking:max）
② 项目切换器：自动发现项目与主会话（只读扫描，约 20ms；子代理会话不再混入列表）
③ 选择投递目标：点击任一会话行（实时/历史）把它设为输入的目标会话（高亮显示），再点一次恢复自动
④ 打开已存在会话：历史会话行点击即选中为目标并定位（切换实时跟随需插件授权）
⑤ 新建会话：插件连通后按钮可用（在 DSH 进程内创建）；未连通时禁用并说明原因，不使用 DSH 凭证绕过权限
⑥ 软件状态面板：本机每个 agent 软件的四态（已连接 / 已打开 · 未连接 / 未打开 / 未下载）；安装=App 包/CLI/配置目录存在性（cc-switch 同款），运行=进程探测，连接=观察通道 45s 内有数据
⑦ 多后端同窗 + 总控投递（M-A/B/C/H + M-D/E 控制层）：Claude Code 转录、Codex rollout、Kimi Code wire 事件流只读观察，与 DSH 会话并列（来源列区分、同目录项目自动归并）。投递：DSH=插件/队列；其余三家经各自 CLI（tmux 在跑则 send-keys，否则无头续会话，回合完成后状态自动回流）。新建/打开 = 终端新窗口

输入如何送达

DSH：授权挂载插件后直投，否则进本地队列（可复制）。Claude Code / Codex / Kimi Code：选中会话为目标后，发送即经 CLI 无头续会话送达（异步执行，状态由观察通道回流）。

安全边界

控制通道只走各 CLI 官方能力（--resume / exec resume / -S），不注入不绕权：各 CLI 自身的权限模式照常生效；无头进程输出仅落 ~/.agent-pet/cli-control/（0600）。
观察数据只读自 ~/.dsh、~/.claude、~/.codex、~/.kimi-code；不接触任何凭证。
